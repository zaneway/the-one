# P0 工程初始化与本地启动说明

## 1. 目标和边界

本文档描述当前初始化工程交付内容，对齐 `The One 长期记忆系统 P0-P1 详细设计.md` 的 P0 阶段。

当前已实现：

1. Go module 和 `cmd/memoryd` 单二进制入口。
2. 默认配置、环境变量覆盖和命令行覆盖。
3. SQLite 打开、目录创建、PRAGMA 初始化。
4. 嵌入式 migration runner 和 `schema_migration` 校验。
5. P0 核心表：`schema_migration`、`local_identity`、`workspace`、`project`、`repo`。
6. SQLite capability 探测：`sqlite`、`fts5`、`sqlite_vec=false`。
7. `memory.health`、`memory.status` 工具注册。
8. stdio JSON 工具服务骨架。

当前 P0 文档只描述基础工程能力。P1 手动记忆能力见 `P1 手动记忆接口与验收说明.md`。

## 3. 配置说明

默认配置可直接启动：

```yaml
storage:
  backend: sqlite
  path: ~/.memoryd/memory.db
  sqlite_vec_enabled: auto
  busy_timeout_ms: 1000

server:
  mcp_addr: stdio

logging:
  level: info
  format: text

embedding:
  provider: none
```

支持环境变量：

| 环境变量 | 含义 |
|---|---|
| `MEMORYD_CONFIG` | YAML 配置文件路径 |
| `MEMORYD_DATA_DIR` | 数据目录，未显式指定 DB 时使用 `<data-dir>/memory.db` |
| `MEMORYD_DB_PATH` | SQLite DB 路径 |
| `MEMORYD_LOG_LEVEL` | `debug/info/warn/error` |
| `MEMORYD_MCP_ADDR` | 当前仅支持 `stdio` |

命令行参数优先级高于环境变量：

```text
--config
--data-dir
--db-path
--mcp-addr
--log-level
```

## 4. 启动和本地调用

构建：

```bash
make build
```

启动 stdio 工具服务：

```bash
go run ./cmd/memoryd serve --data-dir /tmp/memoryd-p0
```

本地 health：

```bash
go run ./cmd/memoryd health --data-dir /tmp/memoryd-p0
```

本地 status：

```bash
go run ./cmd/memoryd status --data-dir /tmp/memoryd-p0 --include-config
```

如果需要提前验证 P1 依赖的 FTS5 能力，应使用 `sqlite_fts5` 构建标签：

```bash
make test-p1-sqlite
make run-status GO_TAGS=sqlite_fts5 DATA_DIR=/tmp/memoryd-p0
```

P0 允许 `fts5=false` 时启动，但 P1 的 `memory.search/context` 不能在该能力缺失时通过验收。

stdio JSON 请求示例：

```json
{"request_id":"req_001","tool":"memory.health","params":{}}
```

响应示例：

```json
{
  "request_id": "req_001",
  "result": {
    "ok": true,
    "version": "v0.1.0-dev",
    "storage": {
      "ok": true,
      "backend": "sqlite"
    }
  }
}
```

## 5. 错误和排障

P0 主要错误：

| error_code | 场景 | retryable |
|---|---|---|
| `CONFIG_INVALID` | 配置解析或校验失败 | false |
| `STORAGE_OPEN_FAILED` | DB 目录创建、打开或 PRAGMA 失败 | false |
| `STORAGE_UNAVAILABLE` | SQLite ping 失败 | true |
| `MIGRATION_FAILED` | migration 执行或 checksum 校验失败 | false |
| `VALIDATION_FAILED` | 工具名或入参错误 | false |

排障入口：

1. 查看 stderr 日志，重点字段为 `db_path`、`mcp_addr`、`version`、`duration_ms`。
2. 调用 `memory.status` 检查 `migrations.dirty`、`fts5`、`sqlite_vec`。
3. migration 文件只允许追加，不允许修改已发布文件；checksum 不匹配会拒绝启动。
