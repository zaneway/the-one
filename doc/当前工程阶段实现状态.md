## 3. P1 手动记忆状态

P1 已完成手动记忆可用闭环，主要能力包括：

1. `memory.remember`
   - 显式写入记忆。
   - 写入 `memory_item`、`evidence`、`memory_evidence_link`。
   - 支持 `review_checkpoint` 手动写入。
   - 同一 scope/type/content 的最小幂等去重。
2. `memory.search`
   - 基于 FTS5 + metadata filter 检索。
   - 支持 scope/type/state 过滤。
   - 支持 `include_archived`。
   - 支持 evidence refs。
   - 返回 `retrieval_trace_id` 占位。
   - 执行 search scope 校验。
3. `memory.context`
   - 基于当前任务检索记忆并构造压缩上下文。
   - 支持 token budget 近似裁剪。
   - 支持用户偏好补充召回。
   - 设计复查任务优先召回 `review_checkpoint`。
   - 读取并注入 checkpoint 结构化字段：
     - 目标文档
     - 复查结论
     - 确认基线
     - 忽略/延期/开放项
     - 下次复查策略
   - 返回 `retrieval_trace_id` 占位。
4. `memory.review`
   - 支持 `list`。
   - 支持 `approve`。
   - 支持 `reject`。
   - 支持 `edit`。
   - 支持 `archive`。
   - 支持 `delete`。
5. P1 数据表：
   - `memory_item`
   - `evidence`
   - `memory_evidence_link`
   - `memory_review`
   - `review_checkpoint`
   - `memory_tombstone`
   - `memory_item_fts`
6. Scope validator：
   - `user_global`
   - `project_local`
   - `repo_local`
   - `session`
7. Content minimization：
   - content 最大长度限制。
   - evidence 最大长度限制。
   - keywords 数量限制。
   - salient spans 数量限制。
   - checkpoint 拒绝 `full_text` 字段。
8. FTS5 `search_text` 构建。
9. archive/delete 一致性：
   - archived 默认不进入检索。
   - deleted 标记终态。
   - delete 写入 tombstone。
   - delete 清理 FTS entry。

P1 当前符合 `P1 手动记忆接口与验收说明.md` 中的核心验收要求。

## 5. P2 Agent 事件捕获状态

P2 已完成事件捕获可用闭环，主要能力包括：

1. `memory.observe`
   - 支持 `session.start`、`session.end`、`task.start`、`task.result`、`tool.call`、`tool.result.summary`、`file.edit.summary`、`conversation.message`、`agent.response.summary`、`user.correction`、`user.declaration`、`agent.decision` 等 P2 事件类型。
   - 成功响应返回 `request_id`、`raw_event_id`、`session_id`、`task_id`、`accepted`、`pipeline`、`deduped`、`capture_level`。
   - 错误响应返回 `request_id`、`error_code`、`message`、`retryable`、`fallback_hint`。
   - `pipeline=raw_event_only`，不写 `memory_item`、`evidence` 或 `async_job`。
2. P2 数据表和 migration：
   - `agent_session`
   - `agent_task`
   - `raw_event`
   - `0004_init_capture.sql`
3. Capture DTO 和校验：
   - 支持 `agent_type`、`workspace_id/project_id/repo_id`、`source_channel`、`actor`、`source_refs`、`capture_capabilities`。
   - `source_refs.capture_method` 支持 `adapter_hook`、`wrapper_log`、`cursor_rule`、`manual_mcp_call`、`filesystem_watcher`、`git_diff`。
   - `source_channel=agent_session` 时必须显式提供 `agent_type` 和 `workspace_id`。
   - 非 `session.start` 的 agent session 事件默认必须带 `session_id`。
4. 内容最小化：
   - 限制 `input_summary`、`output_summary`、`content_summary`、`source_refs`、`keywords`、`salient_spans` 长度和数量。
   - 拒绝 `full_text`、`full_output`、`full_diff`。
   - 内容边界拒绝不写 `raw_event`，但会计入 `capture_quality.content_boundary_rejections`。
5. 幂等去重：
   - 优先按 `content_hash + session_id + event_type` 去重。
   - 无 `session_id` 时按 `content_hash + source_channel + workspace_id + project_id + repo_id + event_type` 去重。
   - 重复事件返回 `deduped=true`。
6. Session/Task 生命周期：
   - `session.start` 可生成 `session_id`，创建 `agent_session` 和 `default_task`。
   - 普通事件可绑定明确 task 或 default task。
   - `task.result` 会更新 `agent_task.status/outcome_summary/ended_at`。
   - `session.end` 会更新 session 状态，并结束 active/default task。
7. Capture quality：
   - 支持 capture level 计算。
   - 记录 session start/end、task result、工具调用、工具结果、文件编辑、对话事件数量、去重次数、内容边界拒绝次数和缺失能力。
8. 捕获诊断 MCP 工具：
   - `memory.capture.sessions`
   - `memory.capture.tasks`
   - `memory.capture.events`
   - `memory.capture.quality`
   - 支持按 session/task/project/repo/agent/event type/source channel 查询。
   - `memory.capture.events` 支持单个 `event_type` 和多个 `event_types` 过滤。
9. Agent 接入样例：
   - `examples/agents/claude-code/README.md`
   - `examples/agents/codex/README.md`
   - `examples/agents/cursor/README.md`
   - Claude Code 样例目标 Level3+。
   - Codex 和 Cursor 样例目标 Level2+，并明确降级边界。
10. P2 验收入口：
   - `scripts/acceptance/p2_capture.sh`
   - `make test-p2-capture`

P2 当前符合 `The One 长期记忆系统 P2 详细设计.md` 中的核心验收要求。

## 7. 当前工程边界

当前工程仍遵守一期总体架构边界：

1. 不保存完整源码。
2. 不保存完整工具 output。
3. 不保存完整 diff。
4. 不保存完整历史对话。
5. `memory.observe` 只写 `raw_event`，不自动写长期记忆。
6. Code Index 与 Memory 分层，当前 Memory 只处理决策、偏好、约束、失败经验、过程规则和 checkpoint。
7. `sqlite_vec=false` 时系统仍可通过 FTS + metadata 工作。
8. 外部 embedding provider 默认为 `none`，不影响 P0/P1/P2 启动和验收。

## 8. 建议下一步

如果继续按分期规划推进，下一阶段应进入 P3，优先实现：

1. `raw_event -> evidence` 自动抽取。
2. memory candidate 生成。
3. Admission Control。
4. `write_temporary`、`write_provisional`、`write_pending_review`、`write_stable` 策略。
5. 高影响记忆进入 Review Queue。
6. 基础 Retention Job。
7. 自动 review checkpoint candidate。
8. async job 和自动写入诊断。

P3 不应改变 P2 `raw_event` append-only 事实层语义，也不应绕过 P1 的 `memory.Service`、scope validator、content minimization 和 repository 事务能力。
