## 5. P2 Agent 事件捕获状态

P2 已完成事件捕获可用闭环，主要能力包括：

1. `memory.observe`
   - 支持 `session.start`、`session.end`、`task.start`、`task.result`、`tool.call`、`tool.result.summary`、`file.edit.summary`、`conversation.message`、`agent.response.summary`、`user.correction`、`user.declaration`、`agent.decision` 等 P2 事件类型。
   - 成功响应返回 `request_id`、`raw_event_id`、`session_id`、`task_id`、`accepted`、`pipeline`、`deduped`、`capture_level`。
   - 错误响应返回 `request_id`、`error_code`、`message`、`retryable`、`fallback_hint`。
   - `pipeline=raw_event_only` 表示 P2 本身只写 `raw_event` 事实层；在 App 装配 P3 automation service 后，会 best-effort enqueue `extract_evidence`，后续由 worker 异步推进自动记忆链路。
2. P2 数据表和 migration：
   - `agent_session`
   - `agent_task`
   - `raw_event`
   - `0004_init_capture.sql`
3. Capture DTO 和校验：
   - 支持 `agent_type`、`workspace_id/project_id/repo_id`、`source_channel`、`actor`、`source_refs`、`capture_capabilities`。
   - `source_refs.capture_method` 支持 `adapter_hook`、`wrapper_log`、`cursor_rule`、`manual_mcp_call`、`filesystem_watcher`、`git_diff`。
   - `source_channel=agent_session` 时必须显式提供 `agent_type` 和 `workspace_id`。
   - 非 `session.start` 的 agent session 事件默认必须带 `session_id`。
4. 内容最小化：
   - 限制 `input_summary`、`output_summary`、`content_summary`、`source_refs`、`keywords`、`salient_spans` 长度和数量。
   - 拒绝 `full_text`、`full_output`、`full_diff`。
   - 内容边界拒绝不写 `raw_event`，但会计入 `capture_quality.content_boundary_rejections`。
5. 幂等去重：
   - 优先按 `content_hash + session_id + event_type` 去重。
   - 无 `session_id` 时按 `content_hash + source_channel + workspace_id + project_id + repo_id + event_type` 去重。
   - 重复事件返回 `deduped=true`。
6. Session/Task 生命周期：
   - `session.start` 可生成 `session_id`，创建 `agent_session` 和 `default_task`。
   - 普通事件可绑定明确 task 或 default task。
   - `task.result` 会更新 `agent_task.status/outcome_summary/ended_at`。
   - `session.end` 会更新 session 状态，并结束 active/default task。
7. Capture quality：
   - 支持 capture level 计算。
   - 记录 session start/end、task result、工具调用、工具结果、文件编辑、对话事件数量、去重次数、内容边界拒绝次数和缺失能力。
8. 捕获诊断 MCP 工具：
   - `memory.capture.sessions`
   - `memory.capture.tasks`
   - `memory.capture.events`
   - `memory.capture.quality`
   - 支持按 session/task/project/repo/agent/event type/source channel 查询。
   - `memory.capture.events` 支持单个 `event_type` 和多个 `event_types` 过滤。
9. Agent 接入样例：
   - `examples/agents/claude-code/README.md`
   - `examples/agents/codex/README.md`
   - `examples/agents/cursor/README.md`
   - Claude Code 样例目标 Level3+。
   - Codex 和 Cursor 样例目标 Level2+，并明确降级边界。
10. P2 验收入口：
   - `scripts/acceptance/p2_capture.sh`

2. 新增 `memory_access_log` 单条和批量写入，支持按 `retrieval_trace_id`、`memory_id`、`event_type` 查询。

5. 查询入口要求 `workspace_id` 或 `retrieval_trace_id/memory_id` 等边界条件，避免诊断查询退化为全库扫描。

当前已完成 P4-B3 code_ref repository：

1. 新增 SQLite code_ref repository，支持写入/更新、按 ID 读取、按 `memory_id` 或 `repo_id + file_path` 查询、解析状态更新、单条删除和按 memory 删除。

当前已完成 P4-B4 docindex repository：

7. 删除 snapshot 时同步删除对应 section snapshot，不影响 `review_checkpoint` 历史结论。

当前已完成 P4-B5 P4 async job handlers：

3. 新增 P4 handler 注册：`resolve_code_ref`、`build_doc_snapshot`、`compute_embedding`、`cleanup_access_log`。

7. `cleanup_access_log` 按默认保留期清理低价值 `retrieved/injected` 明细；用户反馈类事件不在该 handler 中清理。
8. 新增 `memory_embedding` upsert repository，支持同一 memory 多模型 embedding 版本替换。

当前已完成 P4-C1 Orchestrator FTS + metadata 接入：

1. 新增 `retrieval.MemoryOrchestrator`，实现 `memory.RetrievalOrchestrator`，对外保持 `memory.SearchResponse/ContextResponse` DTO 兼容。
2. `memory.search` 在线路径复用现有 SQLite FTS + metadata repository，不重写 P1 检索 SQL，不绕过 scope validator。
3. `memory.search` 会创建 `retrieval_trace(started)`，完成后更新 candidate_count、latency、intent、mode、状态和 fallback reason。
4. `memory.search` 会对 FTS 结果执行 P4 rerank，返回 `score_breakdown`、`why_included`、`retrieval_intent`、`retrieval_mode` 和 used flags。
5. `memory.search` 会写入 `memory_access_log(retrieved)`，包含 rank、score、score_breakdown、inclusion_reason 和 trace 关联。
6. `memory.context` 在同一个 trace 下执行 FTS + metadata 检索，构建最小上下文包，并写入 `retrieved` 与 `injected` access log。
7. `memory.context` 返回 P4 context diagnostics，包括 retrieval intent/mode、预算使用、注入记忆数和 fallback reasons。
8. `internal/app.New` 已默认装配 P4-C1 Orchestrator；`remember/review` 仍保持 P1 服务路径，`search/context` 委托 P4 Orchestrator。
9. trace/access log 写入失败不会阻断检索响应，会记录结构化日志并通过 diagnostics/trace fallback reason 暴露降级。

当前已完成 P4-C2 relation expansion：

1. 新增 retrieval relation DTO，定义 `RelationExpansionQuery`、`RelationExpansion` 和 P4 默认强关系类型：`supersedes/superseded_by/supports/contradicts`。
2. 新增 SQLite relation repository，支持从 seed memory 做 depth=1 outgoing/incoming 边扩展。
3. relation expansion 复用 `memory_item` scope/state 隔离规则，默认排除 deleted/archived，避免跨 project/repo/session 泄露记忆。
4. Orchestrator 在线检索流程改为 `FTS seed -> relation expansion -> candidate merge -> relation-aware rerank`。
5. `supports` 会补充 relation-expanded candidate，并提升 `relation_support`。
6. `supersedes/superseded_by` 会提升新记忆，给被替代记忆增加 staleness penalty，避免旧结论在排序中错误领先。
7. `contradicts` 不默认注入冲突对象，只给已召回候选增加 conflict penalty 和 `contradiction_relation` reason。
8. `memory.search/context` 命中 relation expansion 时返回 `retrieval_mode=fts_relation`、`used_relation=true`，trace 同步写入 `used_relation`。
9. relation repository 缺失或查询失败不会阻断 FTS 检索，会降级为 FTS + metadata 并记录 `relation_unavailable/relation_failed`。

当前已完成 P4-C3 Code Index Adapter：

1. 新增 `internal/codeindex` 包，定义 P4-C3 最小 Adapter 接口、能力声明和 `local_basic` 实现。
2. `local_basic` 支持 repo-relative 文件定位、文件 hash 计算和轻量符号定位；不返回源码正文，不生成调用图或影响面。
3. 新增 `codeindex` 配置，默认 `provider=local_basic`、`max_file_size_kb=512`、`max_resolve_refs=30`；也支持 `provider=none` 显式关闭 Code Index 并降级启动。
4. `memory.search` 增加 `include_code_refs` 入参；`code_task` intent 或显式开启时，Orchestrator 会查询 memory 关联的 `code_ref`。
5. Orchestrator 会在线 best-effort 调用 `local_basic.ResolveCodeRefs`，并把 `resolve_status/content_hash/ref_summary` 写回 `code_ref` 表。
6. `memory.search/context` 可返回已持久化并刷新后的 `code_refs`；context 会聚合使用记忆的 code_refs 到 `context_pack.code_refs`。
7. `resolved/stale/missing/ambiguous/unresolved` 状态会影响 rerank，其中 `stale/missing/ambiguous` 纳入 `staleness_penalty`。

## 7. 当前工程边界

当前工程仍遵守一期总体架构边界：

1. 不保存完整源码。
2. 不保存完整工具 output。
3. 不保存完整 diff。
4. 不保存完整历史对话。
5. `memory.observe` 仍以 `raw_event` append-only 为事实层；P3 自动处理通过 best-effort enqueue 异步推进，不回滚 raw_event。
6. Code Index 与 Memory 分层，当前 Memory 只处理决策、偏好、约束、失败经验、过程规则和 checkpoint。
7. `sqlite_vec=false` 时系统仍可通过 FTS + metadata 工作。
8. 外部 embedding provider 默认为 `none`，不影响 P0/P1/P2 启动和验收。

## 8. 建议下一步

v1.0.0 本地 MVP 已完成。后续建议优先进入：

1. 真实 Codex、Claude Code、Cursor certification 执行和记录归档。
2. access log 敏感删除脱敏和清理前聚合统计表。
3. 后续 vector retrieval 和更强 Code Index Adapter 的可插拔接入。
4. 小团队版本设计。
5. v1.0.0 tag/release 包生成。

P4 不应改变 P2 `raw_event` append-only 事实层语义，也不应绕过 P1/P3 已形成的 repository 事务、scope validator、content minimization、Admission 和 retention 边界。
