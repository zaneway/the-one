# P1 手动记忆接口与验收说明

## 1. 目标和边界

P1 在 P0 工程基座上实现手动记忆可用闭环：

```text
memory.remember
  -> memory.search
  -> memory.context
  -> memory.review/edit/archive/delete
  -> review_checkpoint 手动写入和召回
```

当前已实现：

1. `memory_item`、`evidence`、`memory_evidence_link`、`memory_review`、`review_checkpoint`、`memory_tombstone`。
2. `memory_item_fts` FTS5 虚表，采用 application-managed sync。
3. `scope validator`：`user_global`、`project_local`、`repo_local`、`session`。
4. 内容最小化硬边界：content、evidence、keywords、salient spans。
5. `search_text` 构建。
6. `memory.remember/search/context/review` MCP 工具。
7. 手动 `review_checkpoint` 写入和设计复查 context 召回。
8. archive/delete 后默认检索不再返回旧记忆。

仍不实现：

1. 自动捕获 `raw_event`。
2. 自动 Admission、Retention Job、relation expansion。
3. sqlite-vec 和 embedding。
4. 文档 hash/diff 自动识别。
5. 正式 MCP SDK 绑定。

## 2. 构建要求

P1 依赖 SQLite FTS5。使用 `go-sqlite3` 时需要启用构建标签：

```bash
make build GO_TAGS=sqlite_fts5
```

默认无标签构建允许 P0 启动，但 `memory.remember/search/context` 会因 `FTS_UNAVAILABLE` 无法通过 P1 验收。

## 3. 工具接口

### 3.1 memory.remember

写入用户偏好：

```json
{
  "request_id": "req_001",
  "tool": "memory.remember",
  "params": {
    "content": "用户偏好技术方案先分析架构边界、风险和工程落地，再给实现步骤。",
    "title": "用户偏好：先架构分析再实现",
    "memory_type": "preference",
    "scope": "user_global",
    "source_type": "user_declared",
    "keywords": ["用户偏好", "架构", "风险", "工程落地"],
    "evidence": {
      "interpreted_statement": "用户明确要求技术方案先分析架构边界、风险和工程落地。"
    }
  }
}
```

响应：

```json
{
  "memory_id": "mem_xxx",
  "state": "stable",
  "tier": "durable",
  "deduped": false
}
```

写入设计复查 checkpoint 时，`memory_type=review_checkpoint` 且必须提供 `review_checkpoint`：

```json
{
  "memory_type": "review_checkpoint",
  "scope": "project_local",
  "workspace_id": "ws",
  "project_id": "project_a",
  "content": "总体架构设计已冻结；后续设计复查只关注重大逻辑缺失。",
  "review_checkpoint": {
    "checkpoint_type": "architecture_design_review",
    "review_intent": ["logic_completeness"],
    "target_docs": [
      {
        "path": "The One 长期记忆系统总体架构设计.md",
        "doc_role": "architecture_baseline",
        "content_hash": "sha256:..."
      }
    ],
    "conclusion": "baseline_frozen",
    "confirmed_baseline": ["Code Index 与 Memory 分层"],
    "next_review_policy": {
      "focus": "major_logic_gap_only"
    }
  }
}
```

### 3.2 memory.search

```json
{
  "request_id": "req_002",
  "tool": "memory.search",
  "params": {
    "query": "为什么没有 Kafka",
    "workspace_id": "ws",
    "project_id": "project_a",
    "scope": ["project_local", "user_global"],
    "memory_types": ["decision", "constraint", "failure", "project_fact"],
    "limit": 10,
    "include_archived": false,
    "include_evidence": true
  }
}
```

P1 排序使用：

```text
0.55 * bm25_norm
+ 0.20 * scope_weight
+ 0.15 * confidence
+ 0.10 * importance
- archived_penalty
```

### 3.3 memory.context

```json
{
  "request_id": "req_003",
  "tool": "memory.context",
  "params": {
    "task": "请再次进行设计复查，检查文档完整性",
    "workspace_id": "ws",
    "project_id": "project_a",
    "agent_type": "codex",
    "token_budget": 1200,
    "include_evidence_summary": true
  }
}
```

设计复查任务会优先召回 `review_checkpoint`。P1 不读取当前文档 hash/diff，只把 checkpoint 的目标文档、结论和下次复查策略压缩进上下文。

### 3.4 memory.review

支持动作：

```text
list
approve
reject
edit
archive
delete
```

归档：

```json
{
  "request_id": "req_004",
  "tool": "memory.review",
  "params": {
    "action": "archive",
    "memory_id": "mem_xxx",
    "feedback": "该决策已过期"
  }
}
```

删除：

```json
{
  "request_id": "req_005",
  "tool": "memory.review",
  "params": {
    "action": "delete",
    "memory_id": "mem_xxx",
    "feedback": "误写入"
  }
}
```

删除会：

1. `memory_item.state=deleted`。
2. 写入 `memory_tombstone`。
3. 删除 `memory_item_fts` 中的索引项。
4. 记录 `memory_review(status=deleted)`。

## 4. 错误码

| error_code | 场景 | retryable |
|---|---|---|
| `VALIDATION_FAILED` | 入参缺失或类型错误 | false |
| `SCOPE_INVALID` | scope 与字段不匹配 | false |
| `CONTENT_TOO_LARGE` | 内容超过 P1 边界 | false |
| `MEMORY_NOT_FOUND` | memory_id 不存在 | false |
| `STATE_CONFLICT` | 状态不允许该操作 | false |
| `FTS_UNAVAILABLE` | FTS5 不可用 | false |
| `STORAGE_BUSY` | SQLite busy timeout | true |
| `INTERNAL_ERROR` | 未分类错误 | true |

## 5. 验收命令

运行完整测试：

```bash
make test
make test-p1-sqlite
```

构建并检查能力：

```bash
make build GO_TAGS=sqlite_fts5
bin/memoryd status --data-dir /tmp/memoryd-p1 --include-config
```

期望：

```text
sqlite=true
fts5=true
sqlite_vec=false
migrations.current_version=3
migrations.dirty=false
```

## 6. 关键工程约束

1. P1 所有多表写入都在单个 SQLite 短事务内完成。
2. `archived/deleted` 默认不进入 FTS 检索和 context 注入。
3. `user_global` 不能携带 `project_id/repo_id`。
4. `project_local` 必须携带 `workspace_id/project_id`。
5. `global_common` 不开放给 P1 普通写入。
6. P1 不保存完整工具 output、完整 diff 或完整文档正文。
