# The One 代码阅读指南

> 本文档面向新接手项目的开发者，聚焦"骨架"层面，帮助快速建立全局认知。

---

## 1. 技术栈全景

| 类别 | 技术选型 | 说明 |
|------|---------|------|
| **语言** | Go 1.25 | 纯 Go 项目 |
| **进程间通信** | MCP (Model Context Protocol) over stdio | AI Agent 通过 stdin/stdout JSON-RPC 调用工具 |
| **存储** | SQLite (mattn/go-sqlite3) | WAL 模式，单文件嵌入式数据库，支持 FTS5 全文检索 |
| **配置** | YAML (gopkg.in/yaml.v3) | 支持 CLI flag 覆盖 |
| **日志** | log/slog (标准库) | 结构化日志，输出到 stderr 避免污染 stdio |
| **ID 生成** | 自研 idgen | 前缀 + 雪花式 ID（如 `mem_xxx`、`ev_xxx`） |
| **构建工具** | Makefile | 标准 Go 构建，无额外依赖 |
| **外部依赖** | 仅 2 个第三方包 | 极简依赖：go-sqlite3、yaml.v3 |

**关键设计决策**：零外部服务依赖，embedding provider 默认 `none`，系统仍可运行（降级为 FTS + metadata 检索）。

### 模块职责速查

## 3. 入口点清单

### 3.1 程序入口

| 入口 | 文件 | 说明 |
|------|------|------|
| `main()` | `cmd/memoryd/main.go:20` | 进程入口，调用 `run()` |
| `run()` | `cmd/memoryd/main.go:27` | CLI 命令分发：`serve` / `health` / `status` |

### 3.2 服务启动链路

```
main() → run("serve") → parseConfig() → config.Load()
                                       → app.New(ctx, cfg)    # 组装所有依赖
                                       → App.Serve(ctx)       # 启动 MCP stdio 循环
```

**`app.New()` 初始化顺序**（`internal/app/app.go:35`）：
1. `logging.New()` → 创建 slog logger
2. `sqlite.Open()` → 打开 SQLite，执行 PRAGMA + migration + 能力探测
3. `mcp.NewRegistry()` → 创建工具注册中心
4. `diagnostics.RegisterTools()` → 注册 `memory.health`, `memory.status`
5. `tools.RegisterMemoryTools()` → 注册 `memory.remember/search/context/review`
6. `tools.RegisterCaptureTools()` → 注册 `memory.observe/sessions/tasks/events/quality`
7. `tools.RegisterAutomationTools()` → 注册 `memory.jobs.*`, `memory.candidates.*`, `memory.retention.*`
8. `automation.NewWorker()` → 创建后台 Worker（可选）

### 3.3 MCP 工具入口（16 个工具）

| 工具名 | Handler | 来源模块 | 功能 |
|--------|---------|---------|------|
| `memory.health` | `HealthTool` | diagnostics | 健康检查 |
| `memory.status` | `StatusTool` | diagnostics | 运行状态 |
| `memory.remember` | `Remember` | memory | 写入/更新记忆 |
| `memory.search` | `Search` | memory | 检索记忆 |
| `memory.context` | `Context` | memory | 构建上下文包 |
| `memory.review` | `Review` | memory | 审查记忆（确认/修正/归档/删除） |
| `memory.observe` | `Observe` | capture | 捕获 Agent 事件 |
| `memory.capture.sessions` | `ListSessions` | capture | 查询 Session 列表 |
| `memory.capture.tasks` | `ListTasks` | capture | 查询 Task 列表 |
| `memory.capture.events` | `ListEvents` | capture | 查询 Event 列表 |
| `memory.capture.quality` | `Quality` | capture | 查询捕获质量 |
| `memory.jobs.list` | `ListJobs` | automation | 查询自动化任务 |

## 4. 核心配置文件

| 配置来源 | 路径/方式 | 说明 |
|---------|----------|------|
| **YAML 配置文件** | `-config` CLI flag 指定 | 主配置文件，结构见下 |
| **CLI flags** | `-data-dir`, `-db-path`, `-mcp-addr`, `-log-level` | 覆盖 YAML 配置 |
| **环境变量** | 无 | 当前不支持环境变量配置 |

### 配置结构（`config.Config`）

```yaml
server:
  mcp_addr: "stdio"           # MCP 传输方式，当前仅支持 stdio

storage:
  path: "./data/memoryd.db"   # SQLite 文件路径
  busy_timeout_ms: 5000       # SQLite busy timeout

logging:
  level: "info"               # debug/info/warn/error
  format: "text"              # text/json

memory:
  default_workspace_id: ""    # 默认工作区
  default_user_id: ""         # 默认用户

capture:
  require_session_for_agent_events: true
  max_input_summary_chars: 1200
  max_output_summary_chars: 2000

retrieval:
  default_limit: 10
  default_token_budget: 1800
  online_timeout_ms: 100

embedding:
  provider: "none"            # none/local/openai/deepseek
  model: ""

automation:
  worker_enabled: false       # 是否启用后台 Worker
  poll_interval_ms: 5000
  batch_size: 10
```

## 6. 核心数据模型

### 6.1 记忆领域（`internal/memory/types.go`）

| 类型 | 说明 |
|------|------|
| `MemoryItem` | 核心记忆实体，包含 scope/workspace/user/project 维度隔离 |
| `Evidence` | 记忆的证据来源，一条记忆可有多条证据 |
| `MemoryState` | 状态机：`provisional` → `pending_review` → `stable` / `archived` / `deleted` |
| `MemoryType` | 类型枚举：`decision`, `constraint`, `open_issue`, `failure`, `procedure`, `session_summary` 等 |
| `ContextMemory` | 上下文注入项：压缩后内容 + 包含原因 |

### 6.2 捕获领域（`internal/capture/types.go`）

| 类型 | 说明 |
|------|------|
| `AgentSession` | Agent 会话，包含 agent_type/workspace/project 维度 |
| `AgentTask` | 会话内的任务 |
| `RawEvent` | 原始事件，包含 input/output 摘要、salient spans、keywords |
| `CaptureQuality` | 捕获质量评估 |

### 6.3 SQLite 表结构

| 表名 | 用途 | 关键索引 |
|------|------|---------|
| `memory_item` | 记忆主表 | scope + workspace + type + state |
| `evidence` | 证据表 | memory_id 外键 |
| `memory_evidence_link` | 记忆-证据关联 | 联合主键 |
| `memory_fts` | FTS5 全文索引 | title + content + keywords |
| `agent_session` | Agent 会话 | agent_type + workspace_id |
| `agent_task` | 任务 | session_id 外键 |
| `raw_event` | 原始事件 | session_id + event_type |
| `schema_migration` | 迁移版本 | version 主键 |

## 7. 阅读路径建议

### 快速理解（30 分钟）

1. `cmd/memoryd/main.go` → 理解 CLI 命令分发
2. `internal/app/app.go` → 理解依赖组装和启动流程
3. `internal/mcp/registry.go` → 理解工具注册机制
4. `internal/mcp/stdio.go` → 理解 MCP 协议通信

### 深入记忆系统（1 小时）

1. `internal/memory/types.go` → 领域模型和状态机
2. `internal/memory/service.go` → Remember/Search 业务逻辑
3. `internal/mcp/tools/memory.go` → MCP 适配层
4. `internal/storage/sqlite/memory_repository.go` → 持久化实现

### 深入捕获系统（1 小时）

1. `internal/capture/types.go` → 捕获领域模型
2. `internal/capture/service.go` → Observe 业务逻辑
3. `internal/storage/sqlite/capture_repository.go` → 持久化实现

### 理解配置与迁移

1. `internal/config/config.go` → 配置结构定义
2. `internal/storage/sqlite/store.go` → SQLite 连接和 PRAGMA
3. `internal/storage/sqlite/migration.go` → 迁移引擎
